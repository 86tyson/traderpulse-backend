# Validation checklist

Run through this top-to-bottom before relying on any paper-trade metrics.

---

## 1. Run the backend locally

```bash
cd ~/Desktop/crypto-trading-backend
npm run dev
```

- [ ] Console shows `crypto-trading-backend listening on :3001`
- [ ] No `[config]` startup errors

---

## 2. Confirm backend health

```bash
curl http://localhost:3001/health
```

- [ ] Returns HTTP 200
- [ ] `paperMode: true`
- [ ] `botEnabled` matches your `.env` setting
- [ ] `allowedSymbols` contains the symbols you expect

---

## 3. Confirm Lovable frontend is connected

With the frontend running (`npm run dev` in the Lovable project):

- [ ] Backend status banner shows green "Paper mode · bot enabled" (when `BOT_ENABLED=true`)
- [ ] Account summary loads from backend — shows `Cash $1,000` + zero-quantity holdings
- [ ] Approve / Decline buttons do not throw uncaught errors (toasts only — green for success, red for rejection)

---

## 4. Test Mode validation

Set `BOT_ENABLED=true` on the backend. Open the Test Mode Panel. Run **20 scans** in each regime, then record:

| Regime | Trades taken | Trades filtered | Filter rate |
|---|---|---|---|
| Bullish |  |  |  |
| Bearish |  |  |  |
| Choppy |  |  |  |
| Low volatility |  |  |  |

Expected behavior:

- [ ] **Bullish** → generates several valid trades; most pass the backend (filter rate ≈ 20%)
- [ ] **Bearish** → generates fewer than bullish; most pass (filter rate ≈ 30%)
- [ ] **Choppy** → mostly filters out via no-trade and `CONFIDENCE_TOO_LOW` (filter rate ≈ 80–85%)
- [ ] **Low volatility** → almost always filters out (filter rate ≈ 95%)

Console should show one log line per scan plus a summary at the end. If a regime is wildly outside its expected band, check `MIN_CONFIDENCE` on the backend and the regime probabilities in `mockScanner.ts`.

---

## 5. Confirm test isolation

- [ ] Every row generated by Test Mode shows the **TEST TRADE** badge in the trade log
- [ ] Trade log defaults to **hiding** test trades; counter shows `(N hidden)`
- [ ] Toggling "Show test trades" reveals them
- [ ] Performance panel **excludes** test trades by default
- [ ] Weekly Report **excludes** test trades by default
- [ ] Toggling "Include test trades" on Performance / Weekly Report changes the counts

---

## 6. Paper trade validation (real, non-test)

Use a normal recommendation card (not the Test Mode Panel) so the recommendationId does **not** start with `test-`.

- [ ] Approve one recommendation → green toast `Trade simulated (paper)`
- [ ] New row appears in Trade Log **without** the TEST TRADE badge
- [ ] Performance panel total trade count goes up by 1 (with test trades excluded)
- [ ] Weekly Report total goes up by 1 (with test trades excluded)
- [ ] `data/trading.db` `trades` table contains the row (`sqlite3 data/trading.db "SELECT * FROM trades WHERE recommendation_id NOT LIKE 'test-%' ORDER BY id DESC LIMIT 1;"`)

---

## 7. Failure cases

Each of these should surface a clear, specific UI error — not a silent failure or a stack trace.

- [ ] **Wrong API key:** edit `VITE_BACKEND_API_KEY` to a wrong value, restart `npm run dev` → every authed call shows red toast **Unauthorized**
- [ ] **Bot disabled:** set `BOT_ENABLED=false` on the backend, restart, click Approve → red toast **Bot disabled**, code `BOT_DISABLED`
- [ ] **Backend stopped:** Ctrl-C the backend → within 30 seconds the status banner flips to red **Backend offline**; subsequent action attempts show the same toast
- [ ] **Duplicate recommendation:** click Approve twice on the same card → second click shows red toast **Already processed**, code `DUPLICATE_RECOMMENDATION`

After this section, restore safe defaults:

```bash
# in backend .env
BOT_ENABLED=false
PAPER_MODE=true
```

---

## 8. Hard rule — do not skip

> 🛑 **Do not connect Robinhood or enable live trading until paper trading has at least 50 to 100 real (non-test) paper decisions reviewed.**

That means:

- [ ] At least **50** rows in `trades` where `recommendation_id NOT LIKE 'test-%'` and `status = 'simulated'`
- [ ] You have personally reviewed each row's `entry_reason`, `stop_loss`, `profit_target`, and `confidence_score` and agree the recommendation logic is sane
- [ ] `MAX_TRADE_USD` is set to the smallest amount you can afford to lose
- [ ] `MAX_DAILY_LOSS_USD` circuit breaker is set
- [ ] Robinhood Ed25519 signing has been implemented and tested against a sandbox endpoint
- [ ] The full Safety Checklist in [README.md §"before flipping PAPER_MODE=false"](README.md) has been completed

Until every box on this page is checked, **`PAPER_MODE=true` stays in Railway env**.
